# Environment and reproduction boundaries

The release includes one source snapshot of the maintained Decision Programs implementation. `protocol/core-source.json` records every copied source hash and the public base commit. The snapshot is not a second conversion algorithm; study, training, inference and conversion call the same components. Later generic opt-in code is present in the snapshot but is not enabled by the released 54-feature plans.

The observed native environment was Linux/WSL2, GCC 15.2, CMake 4.2.3, NVCC 13.4.59, nlohmann/json 3.11.3, OpenSSL 3.5.5 and DCMTK 3.6.9. Common Debian package names include `libssl-dev`, `nlohmann-json3-dev`, `libdcmtk-dev`, `dcmtk-data`, `ninja-build`; install a suitable compiler and NVIDIA toolkit separately. Build scripts do not install system packages or change drivers. CUDA architecture 86 matches the measured GPU; other GPUs require their appropriate architecture and new qualification.

The native adapter requires CUDA-enabled XGBoost 3.4.1 and uses its public C API without upstream modifications. A wheel's library can be located with `.venv/bin/python -c "import pathlib,xgboost; print(pathlib.Path(xgboost.__file__).parent/'lib/libxgboost.so')"`. The original native library SHA-256 was `462aa6331ecb178df8d10f16612c865ae70f571c248138e50c8a9eb4bc007dd4`; your installed bytes are separately pinned at run time rather than falsely assigned that hash.

The separately installed CNN environment uses Python 3.12.14 and the observed package versions in `scripts/lesionlocator/requirements.lock.txt`. The setup script uses the PyTorch CUDA 13.2 wheel index to resolve `torch==2.14.0+cu132`. It installs the external GPL source at its pinned commit without editing it. Package availability and compatibility remain platform-specific. The original installation required correcting a malformed ITK 5.4.7 wheel metadata tag; that packaging correction did not change runtime code. This release does not silently apply that environment repair. If encountered, resolve/reinstall the upstream wheel before proceeding.

The full preparation performs two official neural passes per scan: one to retain the original mask/preprocessing and one to extract the frozen continuous/decoder channels, matching the existing workflow. It can take materially longer than the XGBoost evaluation. Reserve local disk for CT, prepared images, 34 CNN fields, 54-column rows and result metadata; the repository excludes all such generated payloads. GPU arrays in the study have a 12 GiB explicit budget; that is not a bound on all driver/native/CNN memory.

No end-to-end clinical preparation/retraining was rerun solely to package this release. Packaging checks cover Python syntax, path arguments, source hashes, cohort/plan invariants and available host tools. A separate staging-built CUDA runtime check inspected both supplied models and found no canonical/compact class differences on 10 synthetic 54-feature rows per model; it read no clinical rows and performed no training. Completed clinical evidence comes from the separately identified frozen runs. Native CUDA sketch/rounding behavior and GPU allocation changes can affect trained trees, so the release does not promise bitwise identical retraining across machines.

The wrapper calls the existing export backend directly with the stable prepared descriptor. This preserves the exported source-descriptor identity for subsequent normalization and channel append; a frontend-created temporary descriptor must not become that persistent provenance path.

If `nvcc` is not on PATH, set `CUDACXX` to its absolute path before running the build wrapper. The packaging smoke build used `/usr/local/cuda/bin/nvcc`; this is a conventional toolkit location, not a required user-directory layout.
